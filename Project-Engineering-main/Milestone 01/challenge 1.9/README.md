# Vibe vs. Pair Challenge

This challenge involves building the same Task Manager application twice to compare two distinct AI-assisted development workflows: **Vibe Coding** (using generative UI/app tools) and **AI Pair Programming** (using editor-integrated assistants). By the end, this project helped me understand the strengths and weaknesses of each approach in terms of speed, control, code quality, explainability, and editability.

## The App You Are Building

I built a standalone Task Manager application with the following required features:

* Add a task with a title
* Mark a task as complete
* Filter tasks by status:

  * All
  * Active
  * Completed
* Clean and simple usable UI

The same exact feature set was built using both approaches.

## Your Folders

* `/vibe-version`: Built using a vibe coding tool (**Google AI Studio**)
* `/pair-version`: Built using an AI pair programming assistant (**GitHub Copilot**)

## Comparison Table

| Dimension          | Vibe Version                                                                                        | Pair Version                                                                                          |                                                        |
| :----------------- | :-------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| **Speed**          | Built in around 6 minutes using Google AI Studio with full UI generated automatically in one prompt | Took around 25 minutes using GitHub Copilot because files, logic, and structure were created manually | Pair version took longer but gave better understanding |
| **Control**        | Limited control because the structure and logic were already generated by the tool                  | Full control over component structure, state management, and functions                                | Pair version better                                    |
| **Code Quality**   | Code worked quickly but some files were larger and less organized                                   | Cleaner code with smaller reusable components and better structure                                    | Pair version better                                    |
| **Explainability** | Harder to explain because generated logic required extra reading                                    | Easier to explain because I built each part manually                                                  | Pair version better                                    |
| **Editability**    | Harder to modify because logic was spread across generated files                                    | Easier to update because I understood the full structure                                              | Pair version better                                    |

## When I Would Use Each Tool

* Vibe coding tool for quick prototype projects and fast UI generation because it creates the full app structure in minutes

* AI pair programming for production-ready projects and assignments where code quality, explainability, and control are important

## Tools Used

* **Vibe tool used:** Google AI Studio
* **Pair tool used:** GitHub Copilot

## Key Observation

Google AI Studio was much faster for generating the initial app and UI, but GitHub Copilot gave significantly better control over code quality, maintainability, and understanding. For fast delivery, vibe coding was better. For long-term maintainable code, pair programming was the better choice.
